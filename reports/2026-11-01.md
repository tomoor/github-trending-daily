### 1. [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem) ✰ 107,834

**解决什么问题**
AI 代理在每次会话开始时缺乏历史上下文，导致无法记住之前的交互和项目细节。  Claude-Mem 通过自动捕获工具使用观察、生成语义摘要，并将其注入到未来的会话中，解决了这一问题，使 AI 能够保持对项目知识的连续性。 

**核心功能**
该项目提供持久化内存、文件夹上下文文件自动生成、多语言模式（支持 28 种语言，包括简体中文）、多种工作流模式切换（如代码、邮件调查）、MCP 搜索工具用于自然语言查询项目历史、知识代理构建、Web Viewer UI 实时可视化内存流、隐私控制以及上下文配置等功能。 

**技术亮点**
Claude-Mem 采用分层架构，核心组件包括 5 个生命周期钩子（`SessionStart`、`UserPromptSubmit`、`PostToolUse`、`Stop`、`SessionEnd`），一个由 Bun 管理的本地 HTTP API Worker 服务，用于存储会话、观察和摘要的 SQLite 数据库，以及用于混合语义和关键词搜索的 Chroma 向量数据库。  它还实现了三层工作流模式的 MCP 搜索工具，通过 `search`、`timeline` 和 `get_observations` 工具，可节省约 10 倍的令牌消耗。 

**适合谁用**
Claude-Mem 适用于使用 Claude Code 或其他支持的 IDE（如 Cursor, Windsurf, OpenCode, Codex CLI, Antigravity CLI, OpenClaw）的开发者和知识工作者。  它旨在帮助 AI 编码助手在不同会话中保持上下文，提高开发效率和代码质量。

### 2. [mattpocock/skills](https://github.com/mattpocock/skills) ✰ 308,352

**解决什么问题**
该项目旨在解决AI辅助软件开发中的四个常见问题：代理未能准确理解用户意图，代理输出过于冗长，代理生成的代码无法正常工作，以及代码库随着AI加速开发而变得复杂难以维护（“大泥球”问题）。

**核心功能**
项目提供了一系列“技能”（Skills），这些技能是模块化的能力，通常基于Markdown并包含前置信息，供编码代理使用。核心功能包括：通过`/grill-me`和`/grill-with-docs`进行“拷问式”对话以明确需求和建立共享语言；通过`/tdd`技能实现测试驱动开发，确保代码质量；通过`/diagnosing-bugs`技能进行系统化的bug诊断；以及通过`/improve-codebase-architecture`技能扫描代码库，发现并改进架构“深化机会”。此外，还有`/to-spec`用于将对话转化为规范，`/to-tickets`用于将计划拆分为可执行的任务票据，以及`/implement`和`/implement-spec`用于执行开发工作。

**技术亮点**
该项目强调“深度模块”设计原则，即通过小接口封装大量功能，提高代码的可维护性和可测试性。它利用“拷问会话”（grilling session）来确保代理与用户之间的理解一致，并建立“通用语言”（ubiquitous language）来减少代理的冗余输出并提高代码库的可导航性。项目还支持多种代理平台（如Claude Code, Codex, GitHub Copilot, Gemini CLI），并提供用户调用和模型调用两种技能触发方式。
