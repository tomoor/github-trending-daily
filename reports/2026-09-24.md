### 2. [google/ax](https://github.com/google/ax) ✰ 9,021

**解决什么问题**
AX 旨在解决在 Kubernetes 环境中运行和管理自主代理的复杂性问题。它通过提供一种声明式的方式来定义代理任务、工作空间、网关和模型配置，从而简化了代理的部署、生命周期管理和调试过程。  传统上，管理大量短生命周期任务作为 Kubernetes CRD 会给 etcd 带来压力，AX 通过将状态存储在 Redis 中并使用 Redis Streams 作为工作队列来解决这个问题。 

**核心功能**
AX 的核心功能包括：
*   **任务管理**：允许用户定义、部署、监控、暂停、恢复和删除代理任务。  任务是隔离执行的最小单元，可以包含容器镜像、命令、计算资源请求和限制等。 
*   **工作空间管理**：提供声明式的工作空间定义，用于配置代理所需的文件系统和工具环境，例如 Git 仓库克隆、MCP 服务器和技能注册表。 
*   **网关管理**：定义任务的网络边界，包括监听器和出站允许列表，以限制代理的网络访问。 
*   **模型配置**：允许集中管理模型配置，包括提供商、模型标识符、生成参数和 API 密钥引用。 
*   **CLI 工具**：提供一个 `kubectl` 风格的命令行工具 `ax`，用于与控制平面交互，执行 `apply`、`get`、`watch`、`ssh` 等操作。 

**技术亮点**
*   **Kubernetes 原生**：AX 控制平面部署在 Kubernetes 集群中，利用 `ko` 工具进行容器镜像的构建和部署。 
*   **高性能状态管理**：使用 Redis 作为状态存储和 Redis Streams 作为 API 服务器和控制器之间的工作队列，以避免 etcd 的性能瓶颈。 
*   **可扩展的控制器**：`ax-controller` 是可水平扩展的工作进程，负责消费 Redis 流、在 Agent Substrate 上配置 atespace 和 actor，并驱动任务达到期望状态。 
*   **灵活的 Runner 机制**：`ax-task-runner` 作为任务容器内的 PID 1 进程，负责准备工作空间、运行命令和提供元数据服务。用户可以自定义 Runner 镜像或嵌入 `runner` 包以实现更高级的定制。 
*   **gRPC API**：控制平面通过 `ax.v1alpha1.AX` gRPC 服务暴露 API，实现任务、网关、工作空间和模型的管理。 

**适合谁用**
AX 适合需要在大规模 Kubernetes 环境中部署、管理和调试自主代理的开发者和团队。  它特别适用于那些希望通过声明式配置来简化代理生命周期管理，并需要对代理的网络行为和资源使用进行精细控制的场景。  此外，对于需要定制代理运行环境或集成特定工具链的用户，AX 提供了灵活的 Runner 扩展机制。

### 4. [BuilderIO/agent-native](https://github.com/BuilderIO/agent-native) ✰ 6,526

**解决什么问题**
Agent-Native 旨在解决传统应用开发中应用与 AI 代理能力分离的问题，通过统一的 `action` 定义，让 UI、代理、HTTP 端点、A2A (Agent-to-Agent) 协议和 CLI 都能调用同一个操作，从而简化开发流程并提升效率。它还通过提供经过人工验证的生产级模块，避免代理从零开始发明，加速开发进程。

**核心功能**
该项目提供了一系列核心功能，包括：
*   **统一的 Action 定义**：一次定义操作，可在 UI、代理、HTTP、MCP、A2A 和 CLI 中复用。
*   **自动状态同步**：代理的更改会更新 UI，UI 状态也对代理可见，实现应用与代理的无缝协作。
*   **SQL 状态与 ORM**：支持持久化应用数据、状态和迁移，且不绑定特定供应商的 schema。
*   **可观测性**：提供 Trace、eval、反馈和审计历史，使代理工作可检查。
*   **多语言支持**：文档网站支持多种语言，包括中文（简体和繁体），确保全球用户都能访问。

**技术亮点**
Agent-Native 的技术亮点在于其模块化框架和对代理的深度支持。它提供了一系列内置模块，如认证与治理、共享能力、实时协作和代理互操作性。项目还强调“源码所有权”，文档和源码位于代理可以检查、fork、eject、patch 或替换的位置。此外，它支持将可视化计划作为 `app-backed skill` 安装，让编码代理能够处理包含图表、线框和原型的结构化计划。

**适合谁用**
Agent-Native 适合希望构建 agentic applications 的开发者和团队。特别是那些需要将 AI 代理能力深度集成到应用中，并希望通过统一的 `action` 定义来提高开发效率的场景。它也适用于需要高度可观测性、模块化和可定制化，并希望拥有源码控制权的开发者。
