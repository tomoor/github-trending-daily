### 1. [lyogavin/airllm](https://github.com/lyogavin/airllm) ✰ 27,046

**解决什么问题**
AirLLM旨在解决大型语言模型（LLMs）在消费级硬件上运行时对GPU内存需求过高的问题。它使得70B参数的模型可以在单个4GB GPU卡上进行推理，而无需进行通常会导致性能下降的量化、蒸馏或剪枝等模型压缩技术。最新版本甚至支持在8GB显存上运行405B的Llama3.1模型。

**核心功能**
该项目的核心功能包括层分片（Layer Sharding），即将模型分解成单独的层并按需加载；层预取（Layer Prefetching），通过重叠计算和I/O操作来提高性能；以及模型压缩（Model Compression），提供4位/8位块级量化，可将推理速度提升高达3倍。它还通过 `AutoModel` 类提供统一的接口，自动检测模型类型并实例化相应的实现。

**技术亮点**
AirLLM的技术亮点在于其内存优化方法，它通过层分片技术，在推理时按层加载模型，而不是一次性加载整个模型。此外，它还支持macOS（通过MLX后端）和CPU推理。模型压缩主要针对磁盘加载瓶颈，通过量化权重来减少磁盘I/O大小，同时保持高精度。项目还集成了RLHF技术，特别是DPO，支持低成本的RLHF训练。

**适合谁用**
AirLLM适合希望在资源有限的硬件（如消费级GPU）上运行大型语言模型的研究人员、开发者和企业。它也适用于需要进行低成本RLHF训练的用户，以及那些希望在不牺牲模型性能的情况下优化LLM推理内存使用的场景。

### 5. [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory) ✰ 12,055

TencentDB Agent Memory 是一个为 Agent 设计的四层本地记忆系统，通过分层记忆和符号化记忆，解决大型语言模型在长对话和复杂任务中面临的上下文限制和记忆效率问题，显著提升 Agent 的性能和准确率。

**解决什么问题**
本项目旨在解决大型语言模型 (LLM) 在处理长对话和复杂任务时遇到的两大挑战：上下文窗口限制导致的信息过载，以及传统记忆系统扁平化存储导致的信息检索效率低下和“幻觉”问题。 它通过智能地管理短期和长期记忆，避免了重复解释、信息丢失和上下文累积压力。

**核心功能**
核心功能包括**符号化短期记忆**和**分层式长期记忆**。 符号化短期记忆将冗长的工具日志压缩成轻量级的 Mermaid 符号图谱，大幅降低 Token 消耗并提升任务成功率。 分层式长期记忆则将对话提炼为 L0 (原始对话) 到 L3 (用户画像) 的语义金字塔，实现渐进式披露和异构存储，确保记忆可追溯和恢复。

**技术亮点**
技术亮点在于其独特的**记忆分层**和**符号化记忆**架构。 记忆分层通过 L0-L3 的语义金字塔（对话、事实、场景、画像）实现知识的结构化存储和渐进式披露，并结合数据库和文件系统进行异构存储。 符号化记忆则利用 Mermaid 图谱表示任务状态，配合 `node_id` 溯源机制，在大幅减少 Token 使用的同时，保证了信息的完整可追溯性。 此外，项目还支持混合检索（BM25 + 向量 + RRF）和白盒可调试性。

**适合谁用**
本项目适合需要提升 Agent 在长对话和复杂任务中表现的开发者和团队。 特别是使用 OpenClaw 或 Hermes 框架的 Agent 开发者，可以作为插件或适配器无缝集成，以节省 Token 消耗、提高任务成功率和 PersonaMem 准确率。 它也适用于希望对 Agent 记忆进行精细化管理、调试和溯源的用户。
