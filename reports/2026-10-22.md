### 1. [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) ✰ 36,349

**解决什么问题**
本项目旨在解决传统安全审计效率低下、覆盖不全的问题。它通过自动化和结构化的审计流程，帮助发现代码库中违反信任边界的漏洞，并提供可复现的证据和最小化的修复建议。

**核心功能**
核心功能包括六个阶段的审计流程：
1.  **侦察**：映射架构、信任边界和输入面，生成 `architecture.md` 和 `coverage-ledger.json`。
2.  **覆盖引导式狩猎**：分配独立的代理执行检查，记录结果，并识别未覆盖的区域。
3.  **候选验证**：独立的验证器尝试反驳发现的漏洞候选。
4.  **结构化输出**：将确认、待验证和已拒绝的记录写入 `findings.json`，并进行验证。
5.  **独立记录验证**：新的代理验证最终的源声明。
6.  **目标中立报告**：从验证过的记录和覆盖账本中生成 `REPORT.md`、`FINDINGS-DETAIL.md` 和 `NEEDS-VALIDATION.md`。

**技术亮点**
该项目采用多代理协调工作，通过严格的沙盒环境确保执行安全。它强调对抗性验证，即检查发现结果的代理与发现结果的代理是独立的，以提高审计的公正性。此外，它支持多次运行以提高覆盖率，并能根据预算和范围调整审计深度。

**适合谁用**
本项目适合需要对代码库进行安全审计的开发者、安全工程师和团队。特别是那些希望自动化安全审查流程、提高漏洞发现效率、并确保审计结果可信赖的用户。它也适用于需要进行渗透测试或专注于特定漏洞研究的场景。

### 2. [vllm-project/vllm](https://github.com/vllm-project/vllm) ✰ 94,847

**解决什么问题**
vLLM 旨在解决 LLM 推理和部署中的性能瓶颈和复杂性问题。 它通过高效的内存管理、连续批处理和优化的内核，显著提高了 LLM 的服务吞吐量，降低了推理成本。

**核心功能**
vLLM 的核心功能包括：
*   **PagedAttention**：高效管理注意力机制中的键值 (KV) 内存，提高内存利用率。
*   **连续批处理**：对传入请求进行连续批处理，以及分块预填充和前缀缓存，以优化吞吐量。
*   **多种量化支持**：支持 FP8、MXFP8/MXFP4、NVFP4、INT8、INT4、GPTQ/AWQ 等多种量化技术，以降低模型大小和计算需求。
*   **优化的注意力内核**：集成了 FlashAttention、FlashInfer 等多种优化注意力内核。
*   **分布式推理**：支持张量、流水线、数据、专家和上下文并行，用于分布式推理。
*   **广泛的模型支持**：无缝集成 Hugging Face 上的 200 多种模型架构，包括解码器模型、MoE 模型、多模态模型等。
*   **OpenAI 兼容 API**：提供 OpenAI 兼容的 API 服务器，方便集成。

**技术亮点**
vLLM 的技术亮点在于其创新的 **PagedAttention** 算法，该算法通过将 KV 缓存视为分页内存，有效解决了 LLM 推理中内存碎片化和利用率低的问题。 此外，它还利用 CUDA/HIP 图、自动内核生成和图级转换等技术，实现了快速灵活的模型执行。

**适合谁用**
vLLM 适合需要高性能、低成本 LLM 推理和服务的开发者、研究人员和企业。 无论是部署大型语言模型、构建 AI 驱动的应用，还是进行 LLM 相关的研究，vLLM 都能提供强大的支持。

*   **自动捕获与整合**：通过生命周期钩子自动记录代理活动（提示、工具调用、会话边界），并将其整合为可读的 Markdown 页面。
*   **零 LLM 默认**：核心捕获、搜索和交接功能无需任何 LLM API 密钥，可在本地运行。

**技术亮点**
*   **混合存储架构**：采用 Git 支持的 Markdown Wiki 作为不可变、可人工编辑的真相来源，结合派生的 SQLite 索引实现高性能搜索和检索。
*   **单二进制 Rust 应用**：整个系统打包成一个自包含的 Rust 二进制文件，简化部署和管理。
*   **记忆分层与衰减机制**：通过结构化的记忆分层和数学衰减公式，防止知识无限增长和上下文污染，并根据访问频率调整记忆保留。
*   **零摩擦捕获**：通过生命周期钩子脚本自动记录代理操作，无需手动干预。

**适合谁用**
`ai-memory` 适合需要为 AI 编码工具提供长期、跨代理记忆的开发者和团队。 尤其适用于频繁切换 AI 代理、在不同项目间工作或在多台机器上协作的用户。 它也适用于希望拥有可审计、可人工编辑的记忆系统，并能根据需求选择是否使用 LLM 的用户。

### 11. [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) ✰ 131,581

**解决什么问题** 
Graphify 旨在弥合开发者自然语言思维与代码实体（文件、函数、关系）之间的鸿沟。它通过将项目内容转化为可查询的知识图谱，使 AI 编码助手能够理解复杂的架构，从而减少手动搜索文件的时间和成本。

**核心功能** 
Graphify 的核心功能包括：将代码、文档、PDF、图片和视频等多种文件类型映射成知识图谱；提供结构化（基于 AST）和语义化（基于 LLM）两种提取方式；支持对图谱进行查询、路径追踪和概念解释；以及通过社区检测识别代码库中的概念模块或子系统。

**技术亮点** 
该项目采用 `tree-sitter` 进行本地代码解析，支持约 40 种编程语言，确保确定性和隐私性，无需 LLM 即可完成代码映射。对于非代码文件，它利用大型语言模型进行语义提取。每个图谱连接都明确标记为 `EXTRACTED`（直接提取）或 `INFERRED`（推断），提高了透明度。Graphify 生成的图谱是可遍历的真实图，而非简单的向量索引。

**适合谁用** 
Graphify 适合使用 AI 编码助手（如 Claude Code, Cursor, Gemini CLI, GitHub Copilot 等）的开发者和团队。它能帮助用户更高效地理解和查询大型代码库，减少 AI 助手在每次会话中重复读取和解释代码的 token 消耗。Graphify Cloud 版本还支持 monorepo 和跨仓库场景，提供形式化验证和 SDLC 全局视角的代码评审功能。
