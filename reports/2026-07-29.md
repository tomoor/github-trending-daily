### 1. [pascalorg/editor](https://github.com/pascalorg/editor) ✰ 18,773

**解决什么问题**
该项目旨在解决传统 3D 编辑器操作复杂、难以与 AI 集成的问题。它通过提供一个无头（headless）的 Model Context Protocol (MCP) 服务器，使得大型语言模型 (LLM) 能够直接读取、修改和管理 3D 场景，而无需浏览器或 GPU。同时，它也提供了一个功能丰富的可视化编辑器，方便用户进行交互式设计。

**核心功能**
核心功能包括：
*   **AI 驱动的场景编辑**：通过 MCP 服务器，AI 代理可以根据自然语言指令生成平面图、翻新房间或执行复杂的空间查询。
*   **3D 可视化编辑器**：提供一个基于 React Three Fiber 和 WebGPU 的交互式 3D 编辑器，支持墙体、区域、物品和楼板等元素的创建和编辑。
*   **场景数据管理**：使用 Zustand 存储管理场景数据，并支持撤销/重做功能。
*   **实时同步**：MCP 服务器与编辑器 UI 可以通过共享 SQLite 数据库和事件流实现近乎实时的场景同步。

**技术亮点**
*   **无头架构**：MCP 服务器在 Node.js 或 Bun 环境中运行，通过 `SceneBridge` 和 Node shims 模拟浏览器 API，实现核心 `@pascal-app/core` 包在非浏览器环境下的运行。
*   **模块化设计**：项目采用 monorepo 结构，将核心逻辑 (`@pascal-app/core`)、3D 渲染 (`@pascal-app/viewer`)、编辑器 UI (`@pascal-app/editor`) 和 AI 接口 (`@pascal-app/mcp`) 分离，提高了可维护性和可扩展性。
*   **WebGPU 渲染**：利用 WebGPU 提供高性能的 3D 渲染能力。
*   **Zod 模式验证**：使用 Zod 定义节点模式，确保数据结构的一致性和有效性。

**适合谁用**
该项目适合需要以下功能的用户：
*   **AI 开发者**：希望通过编程方式或自然语言指令与 3D 场景进行交互，进行自动化设计、内容生成或空间分析的 AI 代理开发者。
*   **建筑师和设计师**：需要一个功能强大、易于使用的 3D 建筑设计工具，并希望利用 AI 辅助设计流程的专业人士。
*   **研究人员**：对 3D 场景理解、AI 与 3D 交互、无头渲染等领域感兴趣的研究人员。

**解决什么问题**

**核心功能**
aisuite 提供两大核心功能：
1.  **统一的聊天补全 API**：提供一个与 OpenAI 兼容的接口，支持多种 LLM 提供商，如 OpenAI、Anthropic、Google、Mistral 等。 开发者只需通过 `<provider>:<model-name>` 格式指定模型，即可在不同提供商之间切换，无需修改代码。
2.  **Agent API**：允许模型调用真实的 Python 函数作为工具，支持多轮对话、工具包（如文件、Git、Shell 操作）以及模型上下文协议 (MCP) 工具集成。  此外，还提供了工具策略、状态存储和追踪等生产级 Agent 所需的功能。

**技术亮点**
aisuite 的技术亮点包括：
*   **提供商无关性**：通过统一的 API 抽象层，屏蔽了底层 LLM 提供商的差异，使得代码更具可移植性。
*   **灵活的工具调用**：支持将普通 Python 函数直接作为工具传递给模型，并自动生成 schema。
*   **Model Context Protocol (MCP) 集成**：原生支持 MCP，允许模型安全地访问外部工具和数据源，如文件系统、Web 搜索等。 
*   **OpenCoworker 应用**：基于 aisuite 构建的桌面 AI 助手，展示了如何利用 aisuite 构建实际的 Agent 应用，可在本地执行任务和自动化。

**适合谁用**
aisuite 适合以下用户：
*   **LLM 应用开发者**：希望快速构建跨多个 LLM 提供商的应用，并简化模型集成和工具调用的开发者。
*   **Agent 开发者**：需要构建具有复杂工具使用、多轮交互和状态管理能力的 AI Agent 的开发者。
*   **希望本地运行 AI 助手的用户**：OpenCoworker 应用为普通用户提供了一个桌面 AI 助手，可以在本地执行任务，保护数据隐私。
