### 1. [pascalorg/editor](https://github.com/pascalorg/editor) ✰ 18,724

**解决什么问题**
本项目旨在解决传统3D场景编辑对人工操作和图形界面依赖的问题，通过引入AI代理，实现3D场景的自动化生成和编辑，从而提高效率并降低专业门槛。它使得大型语言模型（LLMs）能够无头地读取、修改和管理3D场景，而无需浏览器或GPU。

**核心功能**
核心功能包括：
*   **AI驱动的场景编辑**：通过模型上下文协议（MCP）服务器，将自然语言指令转换为Pascal编辑器场景图的结构化操作，例如从文本简报生成平面图或根据照片翻新房间。
*   **无头架构**：MCP服务器在Node.js或Bun环境中运行，通过`SceneBridge`和Node Shims模拟浏览器API，使核心逻辑与渲染逻辑分离。
*   **实时同步与版本控制**：AI代理的修改可以与Pascal编辑器UI实时同步，通过本地SQLite数据库和Server-Sent Events (SSE) 实现，并包含版本检查以避免冲突。
*   **丰富的工具集**：提供创建墙体、物品、开口等核心构建操作，以及场景图的AI可读摘要。还包括视觉工具，如从平面图图像中提取墙体和房间，或从房间照片中识别尺寸和固定装置。

**技术亮点**
*   **Model Context Protocol (MCP)**：实现了MCP服务器，作为AI代理与Pascal场景图和编辑引擎之间的桥梁。
*   **模块化架构**：项目采用Monorepo结构，包含`@pascal-app/core`（核心逻辑）、`@pascal-app/viewer`（3D渲染）、`@pascal-app/editor`（编辑器UI组件）和`@pascal-app/mcp`（MCP服务器）等独立包，确保了清晰的职责分离和可维护性。
*   **Zustand状态管理**：使用Zustand作为核心场景数据的状态管理工具，并结合Zundo实现撤销/重做功能。
*   **多传输选项**：服务器支持stdio、HTTP和内存传输，以适应不同的AI托管环境。

**适合谁用**
本项目适合需要自动化3D场景生成和编辑的AI开发者、建筑师、室内设计师以及任何希望通过自然语言或图像输入来创建和修改3D环境的用户。它特别适用于集成到AI代理（如Claude）中，以实现智能化的设计工作流。

### 4. [andrewyng/aisuite](https://github.com/andrewyng/aisuite) ✰ 15,690

**解决什么问题**
该项目旨在解决大型语言模型（LLM）应用开发中的碎片化问题，通过提供一个统一的 API 接口，开发者无需处理不同 LLM 提供商（如 OpenAI、Anthropic、Google 等）的 SDK 差异。此外，它还简化了 Agent 的构建，使模型能够轻松使用外部工具并执行复杂任务。

**核心功能**
*   **统一的聊天补全 API**：提供一个与 OpenAI 兼容的接口，支持超过 20 个 LLM 提供商，允许通过更改模型字符串来切换模型。
*   **Agent API**：允许模型调用真实的 Python 函数作为工具，支持多轮对话、工具包（文件、Git、Shell）以及模型上下文协议（MCP）工具集成。
*   **OpenCoworker 桌面 AI 助手**：一个基于 `aisuite` 构建的桌面应用程序，能够执行研究、任务处理、文件读写、消息发送以及定时自动化等功能。

**技术亮点**
*   **提供商无关性**：通过 `<provider>:<model-name>` 格式的模型命名，`aisuite` 能够将请求路由到正确的提供商，并标准化请求和响应结构。
*   **灵活的工具调用**：支持将普通 Python 函数作为工具传递给模型，自动生成 schema 并执行调用。
*   **Agent 生产级特性**：Agent API 提供了工具策略、状态存储（内存、文件、Postgres）和追踪功能，以支持长期运行和结构化任务。
*   **本地模型支持**：通过 Ollama 支持本地运行开源模型，无需 API 密钥。

**适合谁用**
*   **LLM 应用开发者**：希望快速构建和部署 LLM 应用，并能在不同模型和提供商之间无缝切换的开发者。
*   **Agent 开发者**：需要为 LLM 构建复杂 Agent，集成外部工具，并管理 Agent 状态和执行流程的开发者。
*   **普通用户**：希望通过桌面 AI 助手自动化日常任务、进行研究和文件处理的用户，特别是那些注重数据隐私的用户，因为 OpenCoworker 的数据保留在本地。
