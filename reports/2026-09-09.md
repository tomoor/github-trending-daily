### 1. [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) ✰ 30,339

**解决什么问题**
该项目旨在解决AI助手输出冗长、包含不必要寒暄或信息组织不清晰的问题，这些问题可能对注意力缺陷多动障碍（ADHD）人群造成理解和执行困难。   它通过提供一套明确的规则，使AI输出更直接、更易于理解和操作。 

**核心功能**
核心功能是根据10条预设规则（例如“以下一步行动开头”、“多步骤任务编号”、“无前言、无总结、无结束语”等）来塑造AI的输出。  这些规则定义在 `skills/i-have-adhd/SKILL.md` 文件中，指导AI生成行动优先、步骤清晰、状态明确、无冗余信息的回复。  

**技术亮点**
该项目采用Markdown作为规则引擎，使得技能逻辑易于理解和修改。  用户可以通过Fork仓库、编辑 `skills/i-have-adhd/SKILL.md` 文件来自定义规则，并将其注册到AI代理（如Claude Code、Codex、Cursor）中。  它支持“始终开启”配置，允许用户将这些规则应用于所有交互，而无需手动触发。 

**适合谁用**
该项目适合任何希望AI助手输出更清晰、更直接的用户，尤其是有ADHD或偏好简洁明了信息的用户。   它也适合开发者和高级用户，他们可以根据个人需求定制AI的响应行为。

### 8. [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills) ✰ 211,431

**解决什么问题**
本项目旨在解决 LLM 在代码生成过程中常出现的几个问题，包括：模型做出错误假设、不寻求澄清、不呈现权衡、过度复杂化代码和 API、堆砌抽象、不清理死代码，以及在不完全理解的情况下修改或删除代码和注释等。

**核心功能**
项目通过四个核心原则来改善 LLM 的编码行为：
1.  **编码前思考**：强制 LLM 明确说明假设、呈现多种解释、适时提出异议并在困惑时寻求澄清，以避免错误假设和隐藏困惑。
2.  **简洁优先**：指导 LLM 编写最少代码解决问题，避免过度工程、不必要的抽象和未请求的功能。
3.  **精准修改**：要求 LLM 只修改与任务直接相关的代码，不“改进”相邻代码、注释或格式，并只清理自己造成的“孤儿代码”。
4.  **目标驱动执行**：将指令式任务转化为可验证的成功标准（例如，通过编写测试），使 LLM 能够独立循环执行并验证结果。

**技术亮点**
本项目将这些行为指南以多种格式分发，以确保与不同的 AI 开发环境兼容。
*   **Claude Code 插件**：通过 `plugin.json` 和 `marketplace.json` 文件，将指南作为可安装的插件提供给 Claude Code CLI 用户。
*   **Cursor 集成**：通过 `.cursor/rules/karpathy-guidelines.mdc` 文件，在 Cursor IDE 中实现规则的自动应用。
