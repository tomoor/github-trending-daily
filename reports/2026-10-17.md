### 5. [mksglu/context-mode](https://github.com/mksglu/context-mode) ✰ 30,221

**解决什么问题**
AI 编码助手面临上下文窗口被工具输出淹没和状态丢失的问题。例如，一个 Playwright 快照会消耗 56 KB 的上下文，而 GitHub issue 会消耗 59 KB。当上下文窗口满时，代理会通过丢弃旧消息来压缩对话，导致工作记忆（如正在编辑的文件、进行中的任务、已解决的错误和用户请求）丢失。

**核心功能**
Context Mode 通过以下三种机制解决这些问题：沙盒执行、知识库和会话连续性。它提供了一套 MCP 工具，如 `ctx_execute` 用于沙盒代码执行，`ctx_index` 和 `ctx_search` 用于知识库管理，以及 `ctx_batch_execute` 用于批量执行。

**技术亮点**
1.  **沙盒执行**: `PolyglotExecutor` 在隔离的子进程中执行 12 种语言的代码，只有结果进入上下文，实现高达 99% 的上下文节省。
2.  **FTS5 知识库**: `ContentStore` 使用 SQLite FTS5 索引内容，支持 BM25 排名、Porter 词干提取、Trigram 子字符串和模糊匹配，实现 99% 的上下文节省。
3.  **会话连续性**: `SessionDB` 捕获事件并存储在持久化存储中，当上下文窗口压缩时，会构建一个 ~2KB 的 XML 恢复快照来恢复代理状态，防止 100% 的状态丢失。

**适合谁用**
Context Mode 适用于使用 AI 编码助手的开发者和工程组织。它支持 17 种 AI 平台，包括 Claude Code、Gemini CLI、VS Code Copilot 和 Cursor 等。对于开发者，它通过节省上下文来提高效率；对于工程组织，它提供了一个平台来洞察团队使用 AI 工具的情况，同时保护隐私。
