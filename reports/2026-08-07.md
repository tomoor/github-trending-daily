### 1. [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory) ✰ 16,310

**解决什么问题**
该项目旨在解决 AI Agent 在使用过程中重复工作的问题，例如项目背景需要反复解释、文档需要重复阅读、已跑通的工作流需要重新摸索等。它通过将有价值的信息保存、组织和复用，让 Agent 能够继承经验，减少返工，提高效率和结果的稳定性。

**核心功能**
TencentDB Agent Memory 提供了四项核心功能：
*   **分层记忆（L0-L3）**：将对话从原始的 L0 对话逐层提炼为 L1 原子记忆、L2 场景记忆和 L3 核心画像，以实现不同粒度的记忆存储和召回。
*   **技能库（Skill）**：Agent 完成复杂工作后，可以从对话和工具调用中提炼可复用的 Skill，并进行版本管理、资源绑定、搜索和路由。
*   **知识地图（Wiki & CodeGraph）**：将文档转化为结构化页面和链接图谱（Wiki），以及索引代码符号、文件、调用关系和影响路径（CodeGraph），帮助 Agent 搜索、阅读和分析。
*   **团队记忆面板（Memory Hub）**：提供统一的管理界面，用于创建团队和 Agent，管理记忆资产的 Owner、版本、状态、可见性，并为 Agent 配装记忆。

**技术亮点**
该项目的主要技术亮点包括：
*   **语义金字塔（Semantic Pyramid）**：通过 L0-L3 的分层记忆结构，解决了传统向量存储中 Agent 容易丢失宏观上下文的问题。
*   **符号上下文卸载（Symbolic Context Offloading）**：用轻量级的 Mermaid 任务图谱替代繁重的工具执行日志，减少了 Token 开销，同时保持了完整的可追溯性。
*   **资产管理**：将 Skill、Wiki 和 CodeGraph 作为一等资产进行管理，支持版本、状态、可见性和 Agent 绑定。
*   **多租户与隔离**：通过 `Team / Agent / Task` 模型确保数据隔离，只有授权用户和 Agent 才能访问。
*   **按需调用知识**：文档和代码作为可用的工具，Agent 通过 `/v3/tools/list` 发现能力，再用 `/v3/tools/call` 按需读取，避免知识整库注入。

**适合谁用**
TencentDB Agent Memory 适合需要构建和管理 AI Agent 团队的个人开发者、小型团队和企业。它特别适用于希望 Agent 能够沉淀经验、减少重复工作、提高协作效率的场景，例如代码开发、文档管理、客户服务等。通过提供统一的记忆管理和资产共享机制，它能帮助 Agent 团队实现经验的复用和积累。

### 3. [cloudflare/computer](https://github.com/cloudflare/computer) ✰ 4,757

**解决什么问题**
该项目旨在解决 AI 代理和分布式应用程序在不同执行环境（如 Linux 容器或动态 Worker）之间共享持久化、标准化工作空间的需求。它通过将 Durable Object 中存储的权威状态投影到各种执行后端，确保文件操作在重启后仍然持久，并在网络边界之间同步。  

**核心功能**
Cloudflare Computer 提供一个持久的、SQLite 支持的虚拟文件系统 (`workspace.fs`)，其 API 类似于 `node:fs/promises`，并支持跨 Durable Object 重启的持久性。  它还提供一个统一的执行接口 (`workspace.runtime.exec()`)，支持多种可插拔的后端，包括完整的 Linux 容器、快速的 Worker Shell 或隔离的 JavaScript 运行时。  此外，它还为 AI 代理提供了现成的 AI SDK 工具（如 `read`、`write`、`edit`、`ls`、`exec`），以及 Git 客户端、R2 支持的只读挂载和文件发布辅助功能。 

**技术亮点**
该项目采用 SQLite 作为 Durable Object 中权威状态的存储，并通过 `capnweb` RPC 协议实现 Durable Object 与 `computerd` 守护程序之间的通信，支持高效的文件变更流和同步。   `computerd` 守护程序在容器内运行，通过 FUSE 将 VFS 挂载到文件系统，使得标准 Linux 工具可以直接操作虚拟数据。  它还支持多种执行后端，包括提供完整 Linux 用户空间的容器、在动态 Worker 中运行的 `just-bash` shell，以及支持持久化导入和 `node:fs/promises` 的隔离 JavaScript 运行时。 

**适合谁用**
Cloudflare Computer 适用于需要小型、可移植工作目录和文件操作工具的 AI 代理和分布式应用程序开发者。  它特别适合在 Cloudflare Durable Objects 环境中构建需要持久化文件系统和灵活执行能力的应用程序。

该项目旨在解决 PDF 文档处理中的效率和质量问题，特别是对于 AI 代理和大型语言模型 (LLM) 流水线。它通过快速识别 PDF 类型（文本型、扫描型、混合型或图像型），避免对文本型 PDF 进行昂贵的 OCR 过程，从而节省成本和时间。此外，它还能从复杂的 PDF 布局中提取高质量的语义信息，而不仅仅是视觉上的保真度。

**核心功能**
`pdf-inspector` 的核心功能包括：
*   **智能分类**：快速判断 PDF 是 `TextBased`、`Scanned`、`ImageBased` 还是 `Mixed` 类型，并在约 10-50 毫秒内完成。它还能识别需要 OCR 的特定页面。
*   **文本提取与布局分析**：将 PDF 内容流操作符解析为带有坐标的 `TextItem` 对象，并检测多列（报纸式）与表格布局，以保留正确的阅读顺序。
*   **表格提取**：采用多种策略（基于矩形、基于线条和启发式）重建表格，无需视觉 OCR。
*   **语义 Markdown 转换**：将字体大小比例、样式和标签化 PDF 结构树转换为 Markdown 标题、列表和代码块。

**技术亮点**
*   **高性能 Rust 核心**：整个库由 Rust 编写，确保了处理速度和效率。
*   **多语言绑定**：提供 Python (通过 `PyO3`)、Node.js (通过 `napi-rs`)  和 WebAssembly 模块，方便集成到不同技术栈。
*   **智能分类与 OCR 路由**：通过 `detector` 模块快速分类 PDF，并根据需要将特定页面路由到 OCR 服务，显著降低处理成本和延迟。
*   **多策略表格检测**：结合矩形、线条和启发式方法，提高了表格识别的准确性。
*   **语义优先的 Markdown 输出**：优化输出以提高 token 效率和语义质量，而非视觉格式，特别适合 AI 代理使用。

**适合谁用**
`pdf-inspector` 适用于需要大规模处理 PDF 文档的开发者、数据科学家和 AI 工程师。特别是那些构建 AI 代理、LLM 流水线或任何需要从 PDF 中快速、准确提取结构化文本的应用。它也适合希望通过避免不必要的 OCR 过程来优化成本和性能的团队。
